## 一、设计目标

将现有"文字卡片堆砌"的四个命理功能升级为**图形化专业命理工具**，与奇门遁甲主盘视觉语言完全统一；同时优化我的页面使其达到专业软件水准。

**核心诉求**：
- 视觉效果：传统方盘/卦象/天地盘的图形化呈现，告别纯文字卡片
- 功能效果：标准排盘 + 核心解读（格局/断语/旺衰/课体等）
- 风格统一：与奇门遁甲主盘（宣纸白+墨色+暗金+楷体）一致

---

## 二、视觉风格统一原则

| 元素 | 规格 |
|---|---|

### 模块 D：梅花易数（meihua）

**输入区**：Tab 切换三种起卦方式
- 时间起卦：年月日时
- 数字起卦：3 个数字（上卦/下卦/动爻）
- 字数起卦：输入文字

**视觉呈现**：

#### D1. 三卦横排（核心）
本卦 / 互卦 / 变卦 三卦并排，每卦六爻纵向显示：

```
   本卦       互卦       变卦
  ━━━○     ━━━      ━ ━
  ━ ━      ━━━      ━ ━
  ━━━      ━ ━      ━━━
  ━ ━      ━━━      ━━━
  ━━━      ━ ━      ━━━
  ━━━      ━━━      ━━━
 火水未济   水火既济   火风鼎
```

- 阳爻：`━━━` 实线
- 阴爻：`━ ━` 断线
- 动爻：阳爻 `━━━○`、阴爻 `━ ━ ×`
- 卦名在卦象下方
- 五行属性标注

#### D2. 卦辞卡
本卦卦辞 + 象辞（出自《周易》原文）

#### D3. 体用生克关系图
```
   体卦 ──生克──> 用卦
   （我）         （事）
        ↓
      断语
```
- 体卦/用卦标注
- 五行生克箭头（生=绿箭头、克=红箭头、比和=灰双向）

#### D4. 断语卡
- 体用关系结论
- 互卦中段提示

- 综合断语（100-200 字）

**算法范围**：本卦（上下卦）、互卦（二三四爻为下互/三四五爻为上互）、变卦（动爻阴阳互换）、体用判定（动爻所在卦为用）、五行生克、断语生成。

## 四、技术实现

### 4.1 前端结构
- 单页应用，沿用 `showPage(name)` 切换机制
- 每个模块独立渲染函数：`renderBazi(r)` / `renderZiwei(r)` / `renderMeihua(r)` / `renderDaliuren(r)`
- HTML 结构在 `public/index.html`，渲染逻辑在同文件 `<script>` 区

### 4.2 算法封装
- 现有 `Features.bazi/ziwei/meihua/daliuren` 基础上扩展
- 每个算法模块独立文件：`public/features/bazi.js` / `ziwei.js` / `meihua.js` / `daliuren.js`
- 算法纯函数，便于单元测试

### 4.3 测试
- 算法单元测试：`tests/bazi.test.js` / `ziwei.test.js` / `meihua.test.js` / `daliuren.test.js`
- 标准测试用例：
  - 四柱：1990-05-15 14:30 男命（庚午辛巳庚辰癸未）
  - 紫微：1995-06-15 10:30 男命（参考 liujixue.cn 标准盘）
  - 梅花：数字 3/8/6 起卦（已知本卦火水未济、变卦火风鼎）
  - 六壬：2026-08-26 22:57（参考 profound 返吟课例）

### 4.4 资源同步
- 前端资源同步至 `public/`、仓库根、`docs/` 三处入口
- 算法模块仅在 `public/features/` 维护，三处入口通过相对路径引用

## 七、风险与边界

### 风险
1. 算法完整性：四柱神煞 20+、紫微格局 30+、六壬九课门等算法复杂，需逐项校验
2. 视觉一致性：5 个模块风格统一需反复调整
3. 工作量：5 模块完整重做，需多轮迭代

### 边界
- 不修改奇门遁甲主盘排盘算法与视觉
- 不修改书院、AI 智能体、会员等既有功能
- 不引入新框架（保持原生 JS + Express）
- 不做后端 API 扩展（除 AI 解读已有接口）
- 算法不做古籍断诀（《穷通宝鉴》《滴天髓》《骨髓赋》《毕法赋》等），仅做标准排盘+核心解读
